===========================================================
TECH STACK — EXACT MAPPING, NOTHING ELSE
===========================================================
React + TypeScript + Tailwind CSS + shadcn/ui frontend.
Supabase backend only: Postgres with the pgvector and PostGIS extensions
enabled, Supabase Auth, Supabase Storage, Edge Functions (Deno/TypeScript),
Supabase Realtime for live job progress. Do not attempt FastAPI, LangGraph,
Celery, Redis, or Chroma — map every one of those to its Supabase
equivalent: FastAPI -> Edge Functions (one function per endpoint/agent).
Pydantic -> Zod schemas, shared in supabase/functions/_shared/schemas.ts.
LangGraph -> a small orchestrator Edge Function (`run-pipeline`) driven by
an explicit DAG table, state kept in `agent_runs`. Celery+Redis -> each
Edge Function invocation runs exactly ONE agent (never a whole pipeline in
one call, to avoid timeouts); a `job_queue` table + pg_cron or self-invoking
functions move the pipeline forward. Redis cache -> a `cache_entries` table
(key, value_json, expires_at). Chroma -> pgvector in the same Postgres.
Cloudflare R2 -> Supabase Storage with private buckets and signed URLs.
Auth0/Clerk -> Supabase Auth. WebSocket/SSE -> Supabase Realtime subscribed
to pipeline_jobs, pipeline_events, agent_runs. Mapbox GL JS runs in the
browser with a public token restricted by URL. Store API keys (Anthropic,
Voyage, Tavily, Google Places, OpenWeatherMap, Gemini image) as Supabase
Edge Function secrets — never expose them to the browser.

===========================================================
ORCHESTRATION
===========================================================
DAG per job: profile (job-level, once) -> recommend (job-level, skipped if
the user chose locations manually) -> then per location: [cultural ||
geo] (parallel) -> analog -> creative (per variant) -> visual (per
variant) -> compliance (per variant) -> risk -> growth -> playbook.
Compliance -> Risk is SEQUENTIAL, not parallel (risk links to compliance
flags, so compliance must finish first). Creative/visual/compliance each
run once per variant (3 variants in MVP). Growth waits until all variants
for that location are done.

Blocking vs non-blocking on failure (after retries):
profile: continue with a minimal profile from raw inputs, Low confidence +
  gap tag.
recommend: fail the job only if there are no user-selected locations;
  otherwise it's simply skipped.
cultural: blocking for creative — fallback to web search first, then a
  Low-confidence minimal result if still empty.
geo: non-blocking — the map shows a gap state instead.
analog: non-blocking — Low confidence, no analog-driven modifications.
creative: blocking for that specific variant only.
visual: non-blocking — sets variants.status = 'brief_only' plus a GapTag.
compliance: non-blocking — shows "Compliance check not completed", never
  shown as a pass.
risk: non-blocking.
growth: non-blocking — strategy section shows a gap.
playbook: always assembles with whatever outputs currently exist.

Scoped re-run dependency table — build this exact logic:
- Edit product basics (name/price/pack/ingredients) -> re-run profile and
  everything downstream of it.
- Add/remove a location -> re-run recommend (partial) + that location's
  full chain; other locations stay untouched.
- Edit a modification (accept/reject) -> re-run creative (affected
  variants) -> visual -> compliance -> risk -> growth; cultural/geo/analog
  stay unchanged.
- Edit a variant's design brief -> re-run visual (that variant) ->
  compliance (that variant) -> risk -> growth; everything else unchanged.
- Regenerate visual only -> re-run visual(variant) -> compliance(variant)
  -> risk; creative and growth stay but growth gets flagged "stale".
- Refresh prices -> re-run only growth's pricing step; everything else
  unchanged.
- Acknowledge/resolve a flag -> no re-run at all.
- Correct an assumption in the profile -> patch profile -> re-run
  everything downstream.
- Regenerate geo -> re-run geo -> growth's distribution section only.
A `rerun` call with dry_run=true must return the exact node list so the
Impact Preview (P-17) can show it before running. Each run increments a
version and keeps the previous output in variant_versions/agent_runs for
History.

Retries/timeouts: LLM calls timeout at 60s with 2 retries (2s, 6s
backoff). Image generation: 90s timeout, 2 retries, then fall back to
brief-only. Places/search/weather: 15s timeout, 2 retries. On a schema
validation failure, send exactly one repair prompt, then fail that node.
Idempotency key = job_id + node_key + location_id + variant_id +
input_hash.
